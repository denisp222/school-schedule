# Данные и публикация

В GitHub входят исходники, искусственные примеры, тесты и инструкции сборки.
Публичный установщик создаёт пустой проект. Он не содержит справочников школы,
учебного плана, расписания, Word-шаблонов школы, диалогов, фотографий или ключей.
Общие шаблоны отчётов создаются программно без исходных школьных документов.

База установленного приложения хранится в
`%LOCALAPPDATA%\SchoolSchedule\Data\schedule.sqlite3`.
Там же остаются история, настройки, локальные копии и личные Word-шаблоны.
Обновление заменяет программу, не базу. Удалять прежнюю версию перед установкой
не нужно. Старые личные шаблоны копируются в папку данных и не отправляются в сеть.

Проверка обновлений делает только GET-запросы к публичным файлам GitHub.
Она не читает расписание и не передаёт имена, документы, диалоги, ключи или
идентификатор компьютера. Как при обычной загрузке файла, GitHub получает
сетевой IP-адрес и технические данные HTTP-соединения. Телеметрии и отправки
журналов нет. Проверку можно отключить в настройках.

Список разрешённых путей Git закрыт по умолчанию. `tools/check_repository.py`
проверяет индекс, запрещённые пути, ключи и фамилии из локального школьного
seed-файла; `--history` проверяет все доступные исторические версии файлов.
Без частного seed-файла остаются проверки путей и ключей. Это не универсальное
распознавание персональных данных: новые текстовые данные нужно проверять.
`tools/check_public_bundle.py` дополнительно проверяет подготовленную программу.
В публикацию отправляются ровно два файла: публичный установщик и подписанный
`update.json`. Маски `dist/*` при публикации не используются.

## Внешний AI и российское законодательство

Проверка обновлений и AI-помощник — разные подключения. Новая установка не
содержит ключа AI. Сохранение и отправка просьбы внешнему AI требуют настройки
пользователем; данные не отправляются автоматически при обновлении или запуске.
При обращении к настроенному AI ему передаются текст диалога и контекст
расписания, в том числе фамилии учителей. Персональных сведений об учениках
в контексте AI нет; произвольный текст пользователя может их содержать.

Само хранение исходного кода без персональных данных на GitHub не размещает
школьную базу за рубежом. Однако локальная база не отменяет требований закона
к работе школы с персональными данными. Для реального применения оператор
данных должен определить основания обработки, права доступа, порядок хранения
и резервирования. Передача контекста иностранному AI требует отдельной оценки
по статье 12 закона № 152-ФЗ, включая применимость уведомления Роскомнадзора,
а локализация — по части 5 статьи 18. Настройка ключа не заменяет правового
основания, согласия или необходимого уведомления.

Эта архитектура уменьшает технический риск публикации школьных данных;
она не является юридическим заключением о соблюдении всех обязанностей школы.
Официальные источники: [законодательство](https://pravo.gov.ru/),
[портал персональных данных Роскомнадзора](https://pd.rkn.gov.ru/).
